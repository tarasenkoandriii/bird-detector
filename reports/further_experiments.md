Нове підтверджене покращення точності не заявляється. Вибірки невеликі; невеликі різниці не доводять статистичної переваги.

## Дзеркальне об’єднання

Оригінальний і горизонтально віддзеркалений кадри проходять модель окремо. Парні рамки з IoU≥0,55 усереднюються з вагами confidence; непідтверджені отримують confidence×0,5; потім застосовується NMS IoU=0,5.

На validation при 640: звичайний прохід 79,46% mAP50–95; контроль із додатковим NMS 78,48%; два проходи з об’єднанням 79,86%. Двопрохідний режим має mAP50 97,28% проти 97,91% початкового. Додатковий прохід та об’єднання витратили близько 119 мс/зображення на CPU цього запуску. Загальна якість неоднозначна, виграш локалізації лише 0,40 пункта, тому режим не додано до основного відеопайплайна. Скрипт залишено для відтворюваних експериментів.

## Повторення

```bash
python compare_models.py --skip-base --sizes 448 512 576 768 --report reports/resolution_refinement_repeat.json
python compare_models.py --skip-base --sizes 960 1280 --report reports/resolution_sweep_repeat.json
python evaluate_quality.py --imgsz 640 --report reports/quality_repeat.json
python evaluate.py --split test --imgsz 512 --report reports/test_512_repeat.json
python evaluate.py --split test --imgsz 640 --report reports/test_640_repeat.json
```

JSON-звіти містять параметри та хеш ваг. Час CPU і MPS не можна порівнювати напряму; паралельні перевірки створюють конкуренцію за ресурси. Офіційний inference-time Ultralytics не охоплює другий прохід усередині update_metrics, тому evaluate_quality.py окремо записує extra_quality_ms_per_image та повний wall_seconds.

## Що далі дасть найбільш корисний експеримент

Потрібна окрема розмічена вибірка реальних відеокадрів: дрібні птахи, рух, перекриття та кадри без птахів. Розділяти за вихідним відео, щоб сусідні кадри не потрапили в різні split. Поточний CUB — фотографії, а демонстраційне відео не має ручних GT-рамок; кількість детекцій на ньому не є recall. Наступне донавчання bbox-гілок слід перевіряти на цій цільовій validation-вибірці, зберігаючи окрему нову test-вибірку недоторканою. Поточні test-результати вже відомі, тож подальший пошук на них створить зміщення оцінки.

## Перевірка реалізації

Усі 15 автоматичних тестів пройшли, включно з віддзеркаленням координат, зваженим об’єднанням та порожніми детекціями. Додаткова перевірка NMS при 512 дала validation mAP50–95 79,67% (reports/nms_512_validation.json). Основний відеопайплайн уже використовує додатковий NMS; його результат не слід ототожнювати з оцінкою без цього кроку. Відеопрохід 512 на MPS завершився без помилки, початковий приклад 640 збережений.
