# Розширений CUB: підготовка та benchmark

8 листопада 2026 року підготовлено окремий однокласовий датасет `datasets/bird-expanded`. Чинний `datasets/bird` та робочі `weights/best.pt` збережені.

## Дані

- Train: **5 377 зображень**, validation: **600**, резервний test: **499**.
- Джерело охоплює 200 видів CUB; усі species об’єднані в один detection-клас bird.
- Train приблизно у 5,4 раза більший за попередні 998 зображень.
- Використано обидва офіційні train-шарди; validation містить попередні 200 і 400 додаткових зображень, які не були попереднім train.
- Test обрано з офіційного test, виключаючи всі зображення попереднього набору. Модель на ньому не запускалася.

Джерело: [Caltech-UCSD Birds-200-2011](https://www.vision.caltech.edu/datasets/cub_200_2011/). Ліцензійні обмеження: некомерційні дослідження та навчання; права на фотографії зберігаються за власниками. Дані доступні через зафіксоване [дзеркало Hugging Face](https://huggingface.co/datasets/bentrevett/caltech-ucsd-birds-200-2011/tree/1ef09e021b0b65b40337f6f285909656f407f6e0/data).

Це більша фотоколекція, не новий відеодатасет. Офіційне джерело попереджає про можливе перетинання CUB із даними попереднього навчання. Резервний test новий щодо наших локальних запусків, але не гарантує відсутності перетинів із pretraining моделі.

## Захист split та аудит

Усі чотири parquet перевірені за зафіксованими SHA256; загальне завантаження близько 1,15 ГБ. Файли й дані не включені до Git та ZIP.

- Виявлено й відхилено 30 некоректних bbox в повному джерелі.
- Старі validation/test не потрапляють у новий train за вихідним SHA256.
- Додаткове порівняння із попереднім test за піксельним хешем та dHash виключило ще одне схоже зображення.
- Нові validation-кандидати перевірені на схожість із попереднім train.
- Пов’язані групи exact/near-дублікатів зведені до одного представника з пріоритетом test → val → train.
- Повторний аудит готового набору: нуль помилок, нуль знайдених пар дублікатів і cross-split leakage.

Near-пошук dHash з порогом Hamming≤4 — евристика: він не доводить відсутності всіх обрізаних чи семантично схожих кадрів. Повний локальний протокол — `datasets/bird-expanded/{source.json,audit.json,manifest.json,summary.json}`; стислий — [expanded_dataset.json](expanded_dataset.json).

## Виміряний бюджет

Коротке реальне навчання bbox-гілок: CPU, 640 px, batch=8, 128 train і 64 validation, одна епоха, той самий AdamW 1e-5. Test відсутній у benchmark YAML. Робочі ваги не замінювалися; benchmark-checkpoint не є релізним кандидатом.

- Навчальна частина: **27,27 с**.
- Перша validation: **11,11 с**; фінальна перевірка checkpoint: **7,67 с**.
- Увесь короткий запуск: **54,81 с**.
- Екстраполяція на 5 377/600: приблизно **20,8 хв на епоху**, **62,5 хв на 3 епохи**.
- Орієнтовний діапазон для 3 епох: **37–87 хв**, плюс невеликі витрати запуску та фінальної перевірки. Це робочий інтервал ±40%, не статистичний довірчий інтервал.

Тривалий нагрів, інші програми, змінна форма зображень і дисковий кеш можуть змінити час. Заміри стосуються лише bbox-гілок; повне розморожування матиме іншу швидкість. Звіт: [expanded_benchmark.json](expanded_benchmark.json).

## Точка відліку для нового навчання

Поточні релізні ваги оцінені на всіх 600 нових validation-зображеннях при 640, CPU, batch=4:

- Precision: **95,28%**, Recall: **95,17%**.
- mAP50: **98,05%**, mAP50–95: **80,24%**.

Звіт: [expanded_baseline.json](expanded_baseline.json). Це baseline до нового навчання, а не результат benchmark-checkpoint. Його не слід напряму порівнювати з 81,41% на попередніх 200 зображеннях: склад validation змінився.

## Відтворення та запуск у Warp

З кореня проєкту й активованим `.venv`:

```bash
# На чистій копії спочатку створити попередню фіксовану підвибірку.
python prepare_data.py
python prepare_expanded.py
python benchmark_expanded.py
```

Якщо `datasets/bird` уже підготовлено, першу команду пропустити. Наявні результати не перезаписуються; для повторного експерименту задавати новий `--out` або `--name`. Розширення потребує `source.json` та `audit.json` попереднього набору, щоб зберегти захист його split. Завантаження використовує системний curl із перевіркою TLS; перевірка SHA256 залишається обов’язковою.

Наступний контрольований запуск (з кореня, macOS):

```bash
mkdir -p work
nohup caffeinate -i .venv/bin/python -u train_boxes.py \
  --data datasets/bird-expanded/data.yaml \
  --model weights/best.pt --imgsz 640 --epochs 3 \
  --lr0 0.00001 --name expanded-bbox640 \
  > work/expanded-bbox640.log 2>&1 < /dev/null &
echo $! > work/expanded-bbox640.pid
```

`nohup` дозволяє закрити термінал, `caffeinate -i` запобігає автоматичному idle sleep під час роботи. Не закривати кришку ноутбука, якщо це переводить його у сон. Checkpoint-и — `runs/experiments/expanded-bbox640/weights/`, журнал — `work/expanded-bbox640.log`. Скрипт зберігає стан після епох; автоматичного відновлення після збою для bbox-етапу ще немає.

Порівняти кандидата з baseline **на тих самих 600 validation-зображеннях при 640**, не зі старими числами для 200:

```bash
python evaluate.py --data datasets/bird-expanded/data.yaml --split val \
  --weights runs/experiments/expanded-bbox640/weights/best.pt --imgsz 640 \
  --report reports/expanded_candidate_validation.json
```

Довгий запуск цією підготовкою не запускається автоматично. Його якість поки невідома. Спочатку лишаємо AdamW і поточні аугментації; MuSGD, mosaic та warmup перевіряти окремими запускaми. Після остаточного вибору кандидата резервний test можна оцінити один раз; не підбирати за ним налаштування.
