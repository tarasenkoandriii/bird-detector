# Покращення моделі — контрольований експеримент

Дата: 8 листопада 2026 року. Усі порівняння й вибір кандидата виконані на тих самих 200 validation-зображеннях. Дані не змінювалися; окремий test оцінено після вибору нових ваг.

## Висновок

Попередній повний fine-tuning погіршив якість відносно сильної початкової YOLO26n. Додавати ще епохи без baseline було необґрунтовано. Замість цього виконано 5 CPU-епох із навчанням лише класифікаційної голови та збереженням backbone/neck/bbox-параметрів.

Нові ваги збережені як `weights/best.pt`; старі — `weights/best_v1.pt`. Результат на validation значно кращий за v1 і близький до початкової моделі. Невеликі відмінності від початкової моделі не мають доведеної статистичної значущості на цій невеликій вибірці.

## Чесне порівняння на validation

| Модель | imgsz | mAP50 | mAP50–95 |
| --- | ---: | ---: | ---: |
| Початкова YOLO26n | 320 | 96.95% | 76.54% |
| Старі ваги v1 | 320 | 48.47% | 15.44% |
| Нові ваги | 320 | 97.04% | 77.58% |
| Початкова YOLO26n | 640 | 97.50% | 78.78% |
| Старі ваги v1 | 640 | 16.63% | 3.60% |
| Нові ваги | 640 | 97.91% | 79.46% |

Точні числа, SHA256, однакові conf=0.001, IoU=0.7, batch=4, CPU — у `model_comparison.json`; v1 — у `v1/model_comparison.json`. COCO bird=14 відфільтровано до NMS та відображено в bird=0. Регресійний тест гарантує, що COCO person=0 не враховується як птах.

Після перенесення класу bird, але **до навчання**, початкова однокласова модель мала mAP50 96.95% та mAP50–95 76.54% — так само, як початкова COCO-модель після правильного відбору bird. Отже, перенесення класу коректне; погіршення v1 виникло в попередньому процесі навчання, а не було необхідною ціною переходу до одного класу.

## Новий режим навчання

- CPU, 5 епох, imgsz=320, batch=8, seed=26.
- AdamW, lr0=0.0001, lrf=0.1, weight_decay=0.0001.
- Без warmup високої bias-LR: warmup_epochs=0, warmup_bias_lr=0.0001.
- Backbone та neck заморожені; bbox-гілки також не навчаються. Навчаються лише cv3 та one2one_cv3 останньої голови.
- BN заморожених частин переведені в режим оцінювання. Після кожної епохи параметри захищених частин порівнюються з початковим станом; усі перевірки пройшли.
- Mosaic=0, scale=0, translate=0; склад даних і split незмінні.
- Найкращий checkpoint обрано за validation fitness, а не за test або відео.

Змінено декілька чинників одночасно. Цей експеримент підтверджує ефективність режиму загалом, але **не доводить**, що єдиною причиною старого погіршення був MPS, learning rate чи конкретна аугментація.

## Окремий test після вибору кандидата

| Метрика | Старі ваги v1 | Нові ваги |
| --- | ---: | ---: |
| Precision | 58.62% | 95.83% |
| Recall | 43.92% | 91.89% |
| mAP50 | 46.79% | 95.33% |
| mAP50–95 | 17.33% | 77.50% |

Test не використовувався для підбору параметрів нового експерименту або confidence. Після нього ваги чи пороги не коригувалися. Невелика вибірка CUB та можливе перетинання з даними предобучення не дозволяють переносити ці числа на довільні відеосцени.

## Помилки за фіксованих conf=0.25 та IoU відповідності 0.5

Ці числа оцінюють відповідність наданим bbox; додаткова справжня птиця без вихідної розмітки може бути зарахована як FP.

| Показник | Старі ваги v1 | Нові ваги | Початкова модель |
| --- | ---: | ---: | ---: |
| TP | 106 | 188 | 189 |
| FP | 95 | 21 | 22 |
| FN | 94 | 12 | 11 |
| Зображення без детекцій | 62 | 7 | 7 |
| Випадки неточної локалізації | 32 | 5 | 4 |

Середній IoU правильних відповідностей: 0.661 → 0.895. Візуально перевірені шість контрольних прикладів вихідної розмітки; це не замінює повного ручного аудиту.

## Реальне відео

Оброблено ті самі 240 кадрів із незмінними conf=0.25, imgsz=640 та додатковим NMS IoU=0.5. Нові ваги дали детекції на **240 із 240 кадрів** проти 170 у v1. Результат: 247 рамок після NMS, жоден кадр не пропущений, збережені FPS, розмір і тривалість. Це якісна демонстрація, не video recall: покадрової еталонної розмітки немає.

Вихідний ролик і кадри оновлені. Джерело, автор і CC BY 2.0 залишаються в THIRD_PARTY.md. Автоматична перевірка всіх кадрів пройшла; рамки переглянуті візуально.

## Відтворення

```bash
python prepare_data.py
python train.py
python compare_models.py
python analyze_errors.py
python evaluate.py --split test --device cpu
python predict_video.py --input examples/input.mp4 --output examples/output.mp4 --overwrite
python -m unittest discover -s tests -v
```

Нове навчання не перезаписує додані ваги; для оцінки свого результату передайте його шлях через --weights або --trained. До і після зміни збережені метрики, історії та ваги. Додатковий test після вибору моделі не є кроком підбору параметрів.

## Подальші покращення

Початкова модель вже дуже сильна на CUB, тому наступний обґрунтований крок — окремі відеокадри з ручною розміткою, негативні сцени, далекі та рухомі птахи. Дані з одного ролика слід тримати в одному split. Нове довге повне навчання без такого контролю не рекомендується.
